# Etapa 6: Integración con inteligencia artificial

Estado: implementada y probada con OpenAI simulado. Sincronización probada contra la web real de Grenlus. Falta la prueba con OpenAI real.

## Recorrido de un turno

1. `TurnProcessor` toma el turno pendiente y verifica que la conversación siga a cargo de la IA.
2. Arma el historial reciente. Las imágenes, documentos y audios se describen en texto.
3. `AssistantService` llama a OpenAI con el prompt de la empresa y las herramientas.
4. Si el modelo pide herramientas, se ejecutan y se le devuelven los resultados, hasta un máximo de vueltas.
5. Se valida que todo importe de la respuesta haya salido de una herramienta.
6. Con la conversación bloqueada, se decide si enviar: no se envía si un operador la tomó o si el cliente escribió de nuevo.

## Herramientas

| Herramienta | Qué hace |
|---|---|
| `buscar_productos` | Catálogo vigente con precios, tamaños de estampa, talles, colores y enlace |
| `calcular_presupuesto` | Precio exacto calculado en Java |
| `buscar_preguntas_frecuentes` | Respuestas cargadas por la empresa |
| `registrar_datos_cliente` | Nombre, localidad e interés |
| `registrar_oportunidad` | Pedido en armado, con presupuesto y diseños adjuntos |
| `derivar_a_operador` | Pasa la conversación a una persona |

La empresa y el cliente salen del turno en curso. El modelo no puede pedir datos de otro cliente ni de otra empresa.

## Regla de precios de Grenlus

Replicada del personalizador de la web, revisado el 2026-11-10:

`precio unitario = precio base + una estampa (la del diseño más grande) + adicional de talle especial + adicional del color`

- Desde 6 unidades del mismo producto, el precio base tiene el descuento mayorista (10 %).
- Talles especiales: T6, T8, T10, T14 y T16.
- Ejemplo verificado: remera talle M con estampa chica = $14.900 + $2.000 = $16.900.

## Protecciones

| Riesgo | Protección |
|---|---|
| Precio inventado | Se pide una corrección; si se repite, se deriva con un mensaje neutro |
| Catálogo viejo (más de 2 horas sin sincronizar) | No se informan precios y se deriva |
| Sin crédito en OpenAI o error persistente | Mensaje neutro y derivación |
| Cliente intenta cambiar las reglas | El prompt trata sus mensajes como datos |
| Datos personales | El teléfono nunca se envía al modelo; OpenAI no guarda la conversación (`store: false`) |

## Proveedor del modelo

El asistente no depende de un proveedor. Se elige en `.env`:

| Variable | OpenAI (pago) | Gemini (gratis para pruebas) |
|---|---|---|
| `LLM_API_FORMAT` | `responses` | `chat-completions` |
| `LLM_BASE_URL` | `https://api.openai.com/v1` | `https://generativelanguage.googleapis.com/v1beta/openai` |
| `LLM_MODEL` | `gpt-6.1-terra` | `gemini-3.6-flash` |
| `LLM_API_KEY` | platform.openai.com | aistudio.google.com |

Sin `LLM_API_KEY`, cada mensaje se deriva a un operador. `LLM_REASONING_EFFORT` vale `low` por defecto.

**El plan gratuito de Gemini no sirve para clientes reales.** Según las condiciones de Google (revisadas el 2026-11-10), en ese plan el contenido se usa para mejorar sus productos, puede revisarlo una persona y se pide no enviar datos personales. En los planes pagos, Google no usa los datos.

Gemini exige reenviar sus mensajes tal cual llegaron para validar las firmas de razonamiento; `ChatCompletionsClient` lo hace.

La sincronización del catálogo se activa con `CATALOG_GRENLUS_API_URL`; vacía, no se sincroniza.

El prompt inicial está en `backend/src/main/resources/assistant/grenlus-system-prompt-v1.md` y se copia a la base la primera vez. Desde ahí se edita sin desplegar; el panel llega en la Etapa 8.
